```text
PRIVATE-TESTNET-RELEASE-001
```

## Scope

This document records the Milestone 2 / v0.9 private-testnet release-gate
package. It does not add new runtime behavior. It consolidates already-merged
Milestone 2 features into a launch-readiness gate and defines the evidence
needed before IAMINE treats the private testnet as operationally stable.

The release gate has two layers:

- repository launch readiness: feature evidence, local validation, TS140 QA,
  Proxmox/R5500 QA, and post-merge validation;
- operational stability: 10-50 nodes, 3-10 operators, multiple physical
  networks, and 2-4 weeks of stable operation.

This feature can close the repository launch-readiness package. It cannot by
itself prove the future operational stability window.

## Release Gate

- all Milestone 2 feature rows are closed in the roadmap;
- private-testnet network compatibility, identity, discovery, admission,
  transport, remote inference, observability, and load-resilience boundaries are
  documented;
- local, TS140, and Proxmox/R5500 validation pass from exact Git identities;
- no runtime code is changed by the release gate itself;
- generated logs and local evidence are not committed;
- optional tools are reported as skipped when unavailable;
- the future operational soak is explicitly not claimed by repository-only QA.

## No-Go Conditions

Do not publish a private-testnet launch package if any of these are true:

- a Milestone 2 dependency is not closed in `develop`;
- private-testnet admission can be bypassed by an unauthorized peer;
- secure transport downgrade is accepted;
- remote inference accepts unbounded, unauthenticated, or inadmissible requests;
- observability emits private host identifiers, addresses, secrets, or user
  paths;
- load-resilience stress reports failed requests, timeouts, duplicate results,
  duplicate executions, duplicate identities, incompatible assignments, or
  lifecycle validation failures;
- QA requires uncommitted source changes to pass;
- the release gate relies on real host identifiers or credentials in repository
  files.

## Privacy And Security

The private-testnet release gate must not collect, persist, log, or commit:

- usernames;
- home directories;
- full hostnames;
- MAC addresses;
- IP addresses;
- serial numbers;
- disk UUIDs;
- machine IDs;
- user process lists;
- personal paths;
- permanent hardware fingerprints;
- wallet keys, private keys, tokens, secrets, or credentials.

SSH aliases may appear in QA instructions. Resolved addresses and credentials
must stay in local SSH configuration and out of repository files.
